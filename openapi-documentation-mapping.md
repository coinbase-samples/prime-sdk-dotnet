# Coinbase Prime SDK .NET - OpenAPI Documentation Mapping

This document provides a comprehensive mapping of documentation available in the OpenAPI specification (`apiSpec/prime-public-spec.yaml`) for key models and enums used in the Coinbase Prime .NET SDK.

## Purpose

This mapping file can be used to regenerate SDK models with proper XML documentation comments, providing developers with rich IntelliSense and documentation while using the SDK.

### Order Model (`coinbase.public_rest_api.Order`)

**Schema Description:** No schema-level description provided

**Properties:**
- `id` (string): The unique order ID generated by Coinbase (example: 82c879c1-84e1-44ed-a8c2-1ac239cf09ad)
- `user_id` (string): The ID of the user that created the order (example: "42")
- `portfolio_id` (string): The ID of the portfolio that owns the order (example: 3e1fe27e-26fe-46d8-b118-c752a2ae6b47)
- `product_id` (string): The ID of the product being traded by the order (example: BTC-USD)
- `side` (ref): OrderSide enum reference
- `client_order_id` (string): A client-generated order ID used for reference purposes (note: order will be rejected if this ID is not unique among all currently active orders) (example: f69a20b1-4ac4-420e-90b5-814a12565bfa)
- `type` (ref): OrderType enum reference
- `base_quantity` (string): Order size in base asset units (either `base_quantity` or `quote_value` is required) (example: "50")
- `quote_value` (string): Order size in quote asset units, i.e. the amount the user wants to spend (when buying) or receive (when selling); the quantity in base units will be determined based on the market liquidity and indicated `quote_value`. Either `base_quantity` or `quote_value` is required (example: "100")
- `limit_price` (string): The limit price (required for TWAP, VWAP, LIMIT and STOP_LIMIT orders) (example: "50.12")
- `start_time` (string): The start time of the order in UTC (only applies to TWAP, VWAP orders.) (example: 2021-05-31T09:59:59Z)
- `expiry_time` (string): The expiry time of the order in UTC (applies to TWAP, VWAP, LIMIT, and STOP_LIMIT orders with `time_in_force` set to `GTD`) (example: 2021-05-31T10:59:59Z)
- `status` (ref): OrderStatus enum reference
- `time_in_force` (ref): TimeInForceType enum reference
- `created_at` (string): The order creation time as a UTC timestamp (example: 2021-05-31T10:59:59Z)
- `filled_quantity` (string): Size filled (in base asset units) (example: "100")
- `filled_value` (string): Market value filled (in quote asset units) (example: "100")
- `average_filled_price` (string): Indicates the average `filled_price` (example: "50.19")
- `commission` (string): Total commission paid on this order (in quote asset units) -- only applicable for partially- or fully-filled orders (example: "4.99")
- `exchange_fee` (string): Fee charged by the exchange for Cost Plus commission configurations. Exchange fee will be 0 for All In commission configurations. (example: "2.50")
- `historical_pov` (string): historical pov for the order (example: "2.50")
- `stop_price` (string): Specifies the stop price at which the order activates. The order is activated if the last trade price on Coinbase Exchange crosses the stop price specified on the order (example: "50.12")
- `net_average_filled_price` (string): Indicates the average `filled_price` net of commissions and fees (example: "57.68")
- `user_context` (string): Indicates a user friendly message for regarding various aspects of the order such as cancellation or rejection reasons (example: User initiated cancellation)
- `client_product_id` (string): The client product ID of the fill indictating the settlment currency (example: BTC-USDC)
- `post_only` (boolean): Post-only flag - indicates whether the order was placed as post-only (title: Post-only flag - indicates whether the order was placed as post-only) (example: true)
- `order_edit_history` (array): The history of order edits (deprecated: use edit_history instead) (title: deprecated: use edit_history instead)
- `is_raise_exact` (boolean): Indicates if this was a raise exact order (size inclusive of fees for sell orders in quote) (example: true)
- `display_size` (string): Display size for the order (example: "10.5")
- `edit_history` (array): The history of order edits (title: Order Edit History)
- `display_quote_size` (string): The maximum order size that will show up on venue order books (in quote currency). (example: "100.50")
- `display_base_size` (string): The maximum order size that will show up on venue order books (in base currency). (example: "10.5")

## Summary of Documentation Quality

### Rich Documentation Available
1. **Order Model**: Excellent property descriptions with examples
2. **Transaction Model**: Good property descriptions with examples
3. **Asset Model**: Good property descriptions with examples
4. **Balance Model**: Excellent property descriptions with detailed explanations
5. **OrderStatus Enum**: Rich descriptions for each status value
6. **OrderType Enum**: Excellent descriptions with Wikipedia links
7. **TransactionStatus Enum**: Very detailed descriptions including terminal/non-terminal status indicators
8. **TransactionType Enum**: Comprehensive descriptions for all transaction types
9. **WalletType Enum**: Clear descriptions for wallet types

### Limited Documentation
1. **Activity Model**: Basic property descriptions, no schema-level description
2. **Portfolio Model**: Basic property descriptions with examples
3. **Wallet Model**: Basic property descriptions with titles
4. **ActivityType Enum**: Extensive enum values but no descriptions for individual values
5. **ActivityStatus Enum**: Basic enum values with no descriptions

### Missing Documentation
- Most schema-level descriptions are missing (models don't have class-level documentation)
- Some enum values lack individual descriptions

## Usage Notes

- The OpenAPI spec contains rich property-level documentation with examples
- Enum documentation quality varies significantly
- Most examples use realistic UUID and timestamp formats
- Status descriptions often include important contextual information (terminal vs non-terminal)
- Some descriptions include deprecation warnings and migration guidance
